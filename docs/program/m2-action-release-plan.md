## Projection contract recommendations

The workflow acquires its lock before prepare starts. prepare must accept trusted release identity/assets plus bounded injected operations, not a preloaded snapshot/context that could have been read before the lock. It calls fresh default config/repository/Pages/store reads itself. Target adopter identity comes from trusted runner GITHUB_REPOSITORY/GITHUB_REPOSITORY_ID corroborated by API, while product code identity separately comes from job.workflow_repository/job.workflow_sha. Config is read at one immutable current default-branch commit. Artifact claims select neither identity.

prepare returns one privately owned AssembledSite, its validated context, immutable retained records selected for comments, source-ordered current-head readiness targets, and bounded fixed deferred diagnostics. It uses real deriveStreams/compareRunOrder and generated pointer bytes. A target is eligible only if the built latest pointer names the newest eligible retained run for the current authenticated PR head; otherwise defer under ADR0016. Closed/unassociated/expired runs do not invent PR targets. Unknown config/store/run versions refuse before deployment/comment mutation.

finish accepts this exact prepared DTO and the official deploy-step observation. It does not read newer store data to select a run that this artifact never served. It invokes actual waitForReadiness with all selected pointers, then real renderComment/reconcileComment. Every POST/PATCH guard re-fetches current PR head, parses the existing numeric-bot comment stamp, compares source order against prepared retained records and checks generation/readiness. An unknown or expired stamp whose order cannot be proved must not authorize rollback. The forge callback runs again after retry backoff. A changed head/pointer defers without rewriting pointer bytes.

Keep independent outcomes: durable source stored/expired/not attempted; official deployment success/failure/cancelled/unknown/not attempted; observed served/pending; each comment unchanged/created/updated/recovered/deferred/failed/disabled. Failure cannot erase an accepted durable run. A failed/cancelled deployment can still be served, and a green deployment is not readiness. Summary repair instructions are fixed trusted commands, not labels/error text. Optional PNG remains omitted with working text link until actual generation/probe/Camo integration is proved.

An ingestion hard refusal for unknown versions must not flow through an unconditional always-project path; the unknown-version product scenario requires zero deployment and comment writes. Successful durable bounded failure/incomplete admission can project. A valid maintenance repair is a separate authorized input, never forged capture evidence.
