## Acceptance evidence and limits

- Barriers force all four readers to fetch before any push, and every named injection point is reached within a two-actor race window for every seed.
- The real Git lease probe forces five rejections per seed, with B's accepted push between each A fetch and stale-lease push. Accepted push bytes remain discoverable after discarding the reply. This proves harness Git mechanics, not production CAS retries/run-key deduplication/site consistency.
- Typed GitHub transport fixtures refuse unknown, duplicate, exhausted and ambiguous-header requests. Auth stripping, bounded fake faults, virtual backoff and accepted-create/lost-reply rediscovery are exercised.
- CDN probes exercise TTL 0/60/600/900 s, separate edges/files, older-after-newer responses, mixed generations and cached 404s whose expiry requires explicit clock advancement.
- Canary assertions cover captured logs, summaries, errors, stored output, normalized traces and temporary Git files. Canary data is refused before Git/CDN writes. The existing no-network guard applies to Vitest and the standalone runner; Git accepts only local file transports.
- Product scenario specifications are written, but their production adapters do not exist. None is counted as passing. Full simulation CI is intentionally non-green for this incomplete coverage, as approved.
