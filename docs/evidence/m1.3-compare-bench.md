# M1.3 comparator: peak RSS and time

Recorded by `node tools/png-bench.ts compare` on 2026-10-01. 02 §5 budget: one
decode/compare at a time within 512 MiB. Policy: comparator-v1 (`COMPARATOR_V1`).

- Machine: AMD Ryzen 5 3600 6-Core Processor, 12 logical CPUs, 16 GiB RAM, win32 10.0.22621
- Node v22.19.0; commit `ead3266`, `packages/core/src` tree `b641682`
- Each row: 3 runs, each in a fresh Node process that reads two PNGs, decodes both
  (`decodePng`), hashes both (`pixelHash`) and compares them. Times are medians in ms. Peak RSS is
  the largest `process.resourceUsage().maxRSS` of the runs, in MiB. It includes Node itself, both
  encoded files and both decoded images.
- Total is everything from the first decode to the end.

| Scenario | Inputs | Outcome | Decode ×2 | Hash ×2 | Compare | Total | Peak RSS |
|---|---|---|---|---|---|---|---|
| pair-baseline | Two 4000×4000 RGBA decoded and hashed, no compare (the RSS floor for the rows below) | no compare | 997 | 335 | – | 1334 | 235 |
| tall-band | 1440×6000 RGB, a 1040×120 band changed | changed (pixels), t0 124,800 px in 1 region | 409 | 180 | 246 | 870 | 178 |
| max-identical | 4000×4000 RGBA (16 MP limit) against itself | unchanged (–), t0 0 px in 0 regions | 992 | 331 | 359 | 1793 | 261 |
| max-sparse | 4000×4000 RGBA, 25 scattered 40×12 blocks changed | changed (pixels), t0 8,000 px in 25 regions | 972 | 329 | 379 | 1725 | 263 |
| max-dense | 4000×4000 RGBA, every pixel changed (one region) | changed (pixels), t0 16,000,000 px in 1 region | 1033 | 320 | 1052 | 2500 | 257 |
| max-stride2 | 4000×4000 RGBA, one pixel in every other tile row and column (62,500 regions) | changed (pixels), t0 62,500 px in 62,500 regions | 1046 | 424 | 463 | 1923 | 268 |
| max-diagonals | 4000×4000 RGBA, every third tile diagonal (long regions, canvas-sized tile rectangles) | changed (pixels), t0 83,334 px in 333 regions | 957 | 324 | 441 | 1742 | 255 |
| max-height | 4000×3000 → 4000×4000 RGBA (height change, padded band) | changed (dimensions), t0 3,937,000 px in 1 region | 921 | 273 | 597 | 1812 | 232 |
| max-dense-worker | Same as max-dense, compared in a PngWorker (images copied in; RSS includes the worker) | changed (pixels), t0 16,000,000 px in 1 region | 1039 | 339 | 1496 | 2926 | 385 |

The comparator never allocates an image-sized buffer. It streams 64-row chunks through the pixel
hash's normalizer and keeps per-tile statistics: 8 bytes per tile per threshold, about 8 MB at
16 MP for v1. The difference from `pair-baseline` is those statistics plus chunk buffers the GC
hasn't collected yet. Region boxes come from each component's tile-rectangle edges, which keeps
the fragmented and diagonal cases linear. The worker row copies both images into the worker, so
the process briefly holds them twice. Only this Windows machine was measured; CI runs the same
code on Linux but doesn't record RSS.
