# 05 · PR comment

MVP: one fixed, trusted renderer and sticky mode only. Configurable blocks and the Studio are
future (`future/comments-studio-and-skills.md`).

## 1. Content

The renderer takes a validated run / `changes@1` projection and builds Markdown with
context-specific encoders. Capture data can't supply templates, raw HTML, links or a
destination. Trusted config controls only: enabled, title, theme preset, display limits.

Order:

1. Source identity and status: run key, captured head SHA.
2. Warnings: failures, incomplete coverage, base-policy problems.
3. Counts.
4. Changed/added/removed rows.
5. Optional bounded PNG preview.
6. Full-report link.

"No visual changes" is allowed only when the declared set is complete and comparable. Even then
it says *declared* coverage. Reproduce PropertyScope's current comment layout as closely as these
rules allow.

## 2. Sticky ownership and ordering

- **Marker:** `<!-- pixelwatch:repo:<numeric-repository-id> -->`. Find and edit only a comment
  with that exact marker **and** the publishing bot's numeric author ID. Never edit a human's
  comment, and don't trust a bot-looking login.
- The target repo and PR come from the authenticated envelope (02 §8), never from the artifact.
- The body includes a bounded machine-readable stamp: run key, captured head SHA, generation.

Reconciliation runs inside the serialized projection job (03 §7), after readiness:

1. For each retained PR needing an update, choose the newest eligible stored run for its
   **current** head (by source order).
2. Immediately before writing, re-fetch the PR head and the existing comment. If the head
   changed, skip and record why; the next capture repairs it. An older publisher can never roll
   a comment back.
3. On a timeout with an unknown create outcome, rediscover the marker before retrying. Bounded
   rate-limit retries.
4. Report stored / deployed / comment status separately. A comment failure never erases a stored
   or deployed run.

GitHub has no atomic "write the comment only if the head is unchanged". A push after the final
check can briefly leave an older head's report, which is why every comment names its SHA.
Serializing only reads, or only deploys, leaves a read-check-write race; the whole
reconciliation stays inside the one lock. All workflows for one site must use the same group.
There's no timeline/thread mode: history lives on the site.

## 3. Size budget

- Cap the final UTF-8 body at **60,000 bytes**, measured after escaping and URL expansion.
- Reserve bytes for the required parts first: identity, status, warnings, full-report link.
  These are never dropped.
- Degrade deterministically:
  1. remove the optional image;
  2. shorten optional rows;
  3. omit optional detail;
  4. fall back to plain text ≤ 8 KiB.
- If GitHub rejects the body anyway, make one fallback attempt, not a truncation loop.
- Sanitize verbose errors into bounded categories. Raw logs never go in the comment or on Pages.
- **Preview image:** static PNG generated by the publisher, with its URL probed first (03 §7). If
  it doesn't render through Camo, the text link remains. Confirm PNG rendering in spike S1.

## 4. Escaping and tests

Encode each context separately: table cells, alt text, code spans, link labels, URLs. Choose a
safe fence delimiter. Strip bidi and control characters, and neutralize `@mentions` from capture
data. The invariant: **visible text equals the canonicalized safe input**.
Build URLs from the configured HTTPS origin/prefix and validated IDs. Reject other protocols,
traversal, userinfo and unexpected hosts.

Test labels containing:

- pipes, brackets, backticks, newlines, quotes;
- HTML and URL delimiters;
- combining characters, emoji, bidi controls;
- `@mentions`.

Adversarial cases:

- spoofed marker or author;
- stale head;
- two racing projectors;
- unknown-create outcome;
- expired preview image;
- the 60,000-byte boundary with multibyte text;
- required-warning retention;
- invalid presentation config (fallback);
- unknown config version (hard failure);
- GitHub rejecting the body (fallback).
