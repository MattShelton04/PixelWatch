# ADR 0024: Observed served readiness through injected adapters

- Status: accepted (implementation inference under ADR 0014)
- Date: 2026-10-03
- Task: M2.3

## Context

ADRs 0004/0005 freeze existing site/latest bytes, three full matching polls at least ten
seconds apart, and readiness observed from the runner. Assembly now supplies real immutable
byte inventories and provenance. Deployment conclusion does not establish served state.
The real forge already has bounded manual-redirect HTTP and injectable deadline/delay ports.

## Decision

Freeze `m2-readiness-contracts.md` and actual root-owned Readiness types before implementation.
Use the existing forge HttpTransport/Timing interfaces plus a monotonic injected `now`.
Production callers supply FetchTransport, RealTiming and performance.now; simulations supply
the actual deterministic clock and no-network transport. Add only the existing internal
`@pixelwatch/forge-github` workspace dependency to publisher; no new external runtime or
development dependency. This is needed for shared HTTP/timing contracts and production ports.

Bound readiness to600000ms and individual requests to min(60000ms, remaining). A full pass
includes site.json and every selected PR pointer, exact generated bytes and provenance.
Every later poll starts after an injected10000ms delay following the prior full poll's
completion. Any failure resets the count. Never claim served at/after the deadline. Race
transport/delay against actual injected deadline and caller abort; no implicit wall-clock
timers in simulations. Invalid/nonmonotonic clock values refuse with fixed diagnostics.

## Consequences

Ready still means observed from one runner, never global visibility. Failed/cancelled deploy
status remains separate from served status. Optional comment previews can use text fallback;
their bounded probe belongs to later comment integration. No served manifest, schema/golden
or changes@1 byte changes. Helper-only readiness cannot activate a full scenario whose
comment ordering would be vacuous; actual serialized projection/comment composition is needed.
Source-ingestion timeout versus already-sent push recovery was clarified separately by the
owner on2026-10-03; its cancellation/preflight implementation is a later dependent slice.
